# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Workflow rules

- For every multi-step build or change: first write out a plan (what changes, which files, how it will be verified), wait for the user's explicit approval, and only then start implementing. Do not begin work on the plan's steps before approval. Trivial single-step edits don't need a plan.

OSISS is an offline multilingual (bn/hi/en) semantic search over institutional PDFs. It returns extractive quotes (no generative answers) with book, page and PDF link. Backend is Python/FastAPI in `src/`; frontend is React + Vite + Tailwind in `frontend/`. See `README.md` for setup and env var docs.

## Commands

Always use the `.venv` interpreter (created by `./setup.sh`); scripts in `src/` use flat imports (`from config import settings`), so run them as files or via the wrappers, not as `python -m src.x` (except uvicorn, see below).

```bash
./setup.sh                      # venv, deps, docker (postgres+ES), schema, model download
./ingestion.sh --once           # ingest new/changed PDFs from data/pdfs/ (omit --once to poll)
./api.sh                        # uvicorn src.api_server:app on :8000
cd frontend && npm run dev      # :5173, proxies /api, /health, /data to :8000 (OSISS_API_URL to change)
cd frontend && npm run lint && npm run build
.venv/bin/python src/db_init.py # idempotent; adds new columns/index after upgrades
.venv/bin/python src/search.py --query "..."   # CLI search

PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest tests                 # unit tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest tests/test_utils.py::test_detect_language_code
```

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` is required: system ROS pytest plugins otherwise crash collection.

## Architecture

Two pipelines share Postgres + Elasticsearch (docker-compose; Postgres on host port **5433**, ES security disabled):

- **Ingestion** (`ingest.py`, helpers in `utils.py`): PyMuPDF text + Tesseract OCR of embedded images per page -> word chunks (300/50 overlap, chunked *per page* so `page_number` stays exact) -> BGE-M3 embeddings -> rows in Postgres `books`/`chunks` and docs in ES index `osiss_chunks` (`_id = book-{id}-chunk-{idx}`). Dedup/re-ingest is keyed on `books.file_path` plus a SHA-256 `file_hash`; a changed file is deleted (PG cascade + ES `delete_by_query` on `book_id`) and re-ingested. Metadata (title/author/year/department) is guessed from the filename only, and is poor for names with hyphens (e.g. both data-structures books get title "DATA").
- **Search** (`search.py`, called by `api_server.py`; model-free helpers in `ranking.py`): `normalize_query` (NFC, invisible chars) -> `translit.query_mode`: *romanized* queries (Indic marker words) search the query as typed plus bn/hi script rewrites (IndicXlit via CTranslate2, `TRANSLIT_*`) fused by RRF; *ambiguous* ones (unknown English words, no markers) are searched as typed and only if the top rerank score is below `TRANSLIT_CONFIDENCE` are the rewrites searched and merged by max rerank score; rerank/QA use the query that scored each chunk best -> two ES searches, kNN on `embedding` and BM25 (`build_keyword_query`: question words stripped, both nukta spellings, `multi_match` over `text` + the query language's `text.bn|hi|en` subfield; bn/hi queries are filtered to same-`language_code` chunks via `KEYWORD_SAME_LANGUAGE`, because against English text their only matchable tokens are stray Latin ones like `b`, which is noise; cross-language matching is left to kNN), fused with RRF (`HYBRID_MODE=rrf`; `sum` = the old single additive query) into `RETRIEVAL_CANDIDATES` chunks -> cross-encoder rerank (`bge-reranker-v2-m3`, skipped if model dir missing or `RERANK_ENABLED=false`) -> `diversify_candidates` (best chunk per page, Jaccard near-duplicate drop, MMR on stored embeddings, `MMR_LAMBDA`) -> extractive QA (xlm-roberta-squad2) on `top_k + QA_EXTRA_CANDIDATES` -> sentence/paragraph extraction around the answer span -> sort by `(1-w)*rerank + w*qa` (`QA_RANK_WEIGHT`), cut to `top_k`, or, when `top_k` is omitted (the website), to hits scoring >= `RESULT_RELATIVE_SCORE` (0.4) x the best, at most `MAX_RESULTS` (`ranking.cut_by_relative_score`; QA then reads `MAX_RESULTS + QA_EXTRA_CANDIDATES` chunks). QA normally uses the Transformers pipeline; if it fails to load, `make_windowed_qa_runner` reads long chunks in 384-token windows (stride 128) and works with slow SentencePiece tokenizers (answers snap to whole words). Models and the ES client are process-wide `lru_cache` singletons (`get_models`, `get_reranker`, `get_es_client`); all models load with `local_files_only=True` from `models/` (download via `src/download_models.py`).
- **API contract**: `api_server.map_result` converts search output to `{exact_quote, book_title, author, department, page_number, pdf_link, paragraph_text}`. `frontend/src/lib/searchApi.ts` normalizes that shape, and the page viewer is an iframe on `pdf_link#page=N`. Stored `page_number` is the PDF page position, not the printed page number.
- All settings are env-driven in the frozen `Settings` dataclass in `config.py` (read at import time; tests/sweeps override with `object.__setattr__(settings, ...)`).

Ingestion OCRs whole pages when a PDF's text layer is unusable (`utils.choose_ocr_language`: legacy-font Bengali/Hindi like Kruti Dev/Bijoy, symbol garbage, scans in Indic scripts); the decision is per book from ~12 sampled pages and leaves normal books on the old path. `src/ingest.py --only NAME...` limits a run to PDFs whose file name contains one of the substrings. `src/build_english_vocab.py` writes `models/english_vocab.txt` (corpus + system word list), which `translit.looks_romanized` uses to tell English from romanized queries.

Chunks get an `is_exercise` flag (`utils.is_exercise_chunk`, a deliberately conservative heuristic) that `retrieve_top_chunks` filters out via `EXCLUDE_EXERCISES`; after changing the heuristic, re-apply it to existing data with `src/backfill_exercise_flags.py` (updates PG + ES in place, no re-embedding). Chunk-boundary changes (e.g. `MIN_CHUNK_WORDS` tail merging) only take effect for newly ingested/re-ingested books.

Changing the ES mapping or embedding dim generally requires recreating the index (`db_init.py` only creates it if absent) and re-ingesting. Adding subfields is the exception: `db_init.py` puts the `text.bn|hi|en` multi-fields on an existing index and `src/reindex_es.py` fills them for existing docs via `_update_by_query` (no re-embedding; only docs missing `text.en` unless `--all`).

## Rich results (website)

`/api/search/rich` (the web UI; `/api/search` is unchanged) adds per-hit `kind`, `blocks` (definition/list/code), `figures`, `tables`, `formulas`, `page` (image + highlight rects as page fractions) and a top-level `layout` (`answer|visual|table|compare|steps`). `src/page_assets.py` (PyMuPDF heuristics) analyses each page once into `ASSET_DIR/<file_hash>/p{N}.json` + WebP crops, served by `/data/assets/<hash>/<name>.webp` (only `p\d+(-[ftm]\d+)?.webp`; the JSON stays private). Built at ingestion, by `src/build_page_assets.py` for existing books, or lazily per page by a search; bump `ASSET_VERSION` after changing the extractor so cached pages rebuild. Pages without a usable text layer are OCRed on first display (`add_ocr_text`) for highlighting. `src/layout.py` is model- and PDF-free (quote alignment, list/code/definition detection, asset ranking, `choose_layout`); test it with hand-written page dicts (`tests/test_layout.py`); `tests/test_page_assets.py` builds a synthetic PDF. PyMuPDF calls in the API process go through `page_assets._RENDER_LOCK`. Frontend: `components/layouts/ResultsView.tsx` switches on `layout.kind`; blocks in `components/blocks/`; non-component helpers live in `lib/results.ts` (react-refresh lint rule).

## Context Explorer

`src/concepts.py` (model- and service-free) builds a concept graph from chunk text, bold lines and figure captions of the page-asset cache: definition / gloss / bold candidates, gloss-only cross-language merging (embeddings measured too unreliable for short terms), `supported()` + `acceptable()` filters, NPMI links needing 2+ prose sentences, pattern relation types, order hints. `src/build_concepts.py` runs it and `concept_store.write_graph` replaces the `concepts` / `concept_mentions` / `concept_links` / `concept_figures` tables in one transaction (ids change on every rebuild; the API's index cache lives 60 s). `src/concept_api.py` serves `/api/concepts*` and `concepts_in_text` (concept links on rich results). Check quality with `build_concepts.py --dry-run --samples 30` and judge samples by hand; `tests/test_concepts.py` (strings) and `tests/test_concepts_db.py` (throwaway `osiss_test` DB). Frontend: `#/explore/<id>` hash routes (`lib/route.ts`), `pages/ExplorerPage.tsx`, `components/explorer/`; the graph layout is our own (`lib/forceLayout.ts`), no d3. `OSISS_API_URL` points the Vite proxy at another API port.

## Library

`src/library.py` + `src/library_api.py` serve `/api/library*` (public like search): book list with cover (first non-blank `p{N}.webp`, blank pages are < 4 KB), counts, the PDF outline (`get_toc`), key concepts (from `concept_mentions`), captioned figures and page images (missing ones built via `page_assets.ensure_pages`). PDF / asset facts are cached per file hash for 10 min. Search inside a book: `book_id` on `/api/search/rich` sets a context variable in `search.py` (`_book_scope`) that `build_knn` / `build_keyword_query` turn into a `book_id` filter; it is part of the answer-cache key. Tests: `tests/test_library_db.py` (throwaway DB + synthetic PDF with an outline). Frontend: `pages/LibraryPage.tsx` (shelves by `department`), `pages/BookPage.tsx`, `components/library/BookCover.tsx`.

## Scholar accounts and workspace

`src/accounts.py` (scrypt password hashes, session tokens stored as SHA-256, failed-login lockout in `user_login_failures`) and `src/workspace.py` (evidence items, collections, notes, activity, dashboard, export) are model- and framework-free and take a psycopg2 connection; every workspace query includes `owner_id`, so another user's ids simply find nothing. `src/accounts_api.py` serves `/api/auth/*` (HttpOnly SameSite=Lax cookie `osiss_session`; `current_user` is the dependency, mutating requests must be same-site, and a user with `must_change_password` is blocked from `/api/workspace/*`), `src/workspace_api.py` serves `/api/workspace/*`; neither is under `PUBLIC_PREFIXES` (no search-access rule or CORS). Evidence items copy title/author from `books` at save time (never from the request) and dedupe on a hash of the whitespace-normalized quote. `REGISTRATION_MODE` is `open` or `closed`; with no email, the admin resets passwords via `/api/admin/users/*` (admin app page `Scholars`). Tests: `tests/test_accounts_db.py` (throwaway DB; includes cross-user isolation). Frontend: `lib/auth.ts` + `components/AuthProvider.tsx`, `lib/workspaceApi.ts`, `components/SaveButton.tsx` (in `SourceFooter` and the concept header), `pages/AccountPage.tsx`, `pages/WorkspacePage.tsx` + `components/workspace/`; routes `#/account`, `#/workspace[/collections|notes[/<id>]]`. Phase 4A/4B (board, study, alerts) are below; sharing (4C) and teacher reading lists (4D) are deferred (README section 16).

## Projects, reader, printed page numbers (workspace phase 2)

Projects: `projects`, `project_books`, `project_evidence` (many-to-many with evidence items) and `notes.project_id` (`workspace.py`, `/api/workspace/projects*`; a project's search is just `book_ids` on `/api/search/rich`: `search._book_scope` holds a tuple of ids and `scope_filters()` makes a `term` or `terms` filter; the answer-cache key includes the sorted set). Highlights are evidence items of kind `highlight` whose `meta.rects` are page-fraction line rectangles (validated by `clean_rects`; dedupe hash includes the rects). The reader endpoint `library.page_detail` serves the page image plus word boxes from the page-asset JSON as fractions (pages without a usable text layer are OCRed on first display, like search highlights); frontend `pages/ReaderPage.tsx` does selection with the pure helpers in `lib/selection.ts` (`tests/selection.test.ts`). `user_activity.page_number` stores reading progress.

Printed pages: `src/page_labels.py` (pure) resolves the label printed on a page: admin-set `books.page_offset` first, else the PDF's own labels kept in `books.page_labels` (JSONB; NULL = not read yet, `[]` = none; filled lazily by `library.book_label_info` or `src/build_page_labels.py`), else none. `books.publisher/edition/isbn` live in PostgreSQL only (search reads title/author/department from ES, so no reindex). `/api/search/rich` adds `printed_page` per hit and workspace evidence carries `printed_page`; `page_number` everywhere remains the PDF position. `admin.METADATA_FIELDS` now includes these fields, so re-ingest and restore keep them. `GET /api/admin/books/<id>/page-offset-guess` only suggests an offset (needs agreement on >= 70% of sampled pages); the admin app confirms it. Tests: `tests/test_page_labels.py`, plus the project/highlight cases in `tests/test_accounts_db.py` and the reader cases in `tests/test_library_db.py`.

## References and writing studio (workspace phase 3)

`src/citations.py` (pure) formats books in APA 7 / MLA 9 / Chicago author-date / IEEE via `Citer(style, books)` (`cite` per in-text citation in document order, since IEEE numbers by first use; `bibliography`; same author + year get a/b letters in APA and Chicago), parses the free-text `author` field (`;`, `&`, `and`; organisations and non-Latin names stay whole), and writes BibTeX / RIS. Formatted text carries `*italic*` markers; `citations.render(text, plain|html|md|latex)` and `citations.runs` consume them. Pages cited are the printed label, else "PDF p. N". `src/quotes.py` (pure) is the integrity check: `verify(quote, page_text)` compares after dropping whitespace, hyphens/dashes, case and quote-mark variants; `[...]`, `…` and `[inserted words]` split the quote into ordered segments. `src/drafts.py` holds the draft format (`[@e<evidence id>]` tokens, `> ` block quotes, inline “quotes” followed by a token), `render`, `check` (injectable `page_text(book, page)`; neighbouring pages are tried, giving `other_page`), the `drafts` table CRUD, and the reference helpers (`reference_books`, `reference_entries`, `bibtex_file`, `ris_file`); a cited item must belong to the draft's owner or it renders "[source missing]". `src/exporters.py` writes `.docx` (python-docx, a new dependency), a LaTeX zip (`draft.tex` + `references.bib`, XeLaTeX) and Markdown; PDF is the browser's print of the preview (`html.print-draft` in `index.css`). Routes: `/api/workspace/drafts*` (CRUD, `/render`, `/check`, `/export?format=docx|tex|md`) and `/api/workspace/references` (`format=json|bibtex|ris`). Tests: `tests/test_citations.py`, `tests/test_quotes.py`, `tests/test_drafts.py` (no services), draft/reference cases in `tests/test_accounts_db.py`, `drafts.page_text` in `tests/test_library_db.py`; frontend `lib/richText.ts` (`tests/richText.test.ts`), `components/workspace/WritingView.tsx`, `ReferencesView.tsx`. Deferred on purpose: chapters/editors/translators, Harvard/Vancouver, bilingual glossary.

## Research board, study and alerts (workspace phase 4A/4B)

Board (`src/board.py`, tables `board_nodes` / `board_edges`, owned through `projects.owner_id`): nodes are claim / evidence / concept / note, edges supports / contradicts / explains / relates; pure helpers `unsupported_claims`, `outline_body` (claims top-to-bottom as headings, supporting evidence as `> quote [@e<id>]`, `TODO` for unsupported claims), `grid_position`, `ring_positions`; `seed_concept` adds a concept and its strongest neighbours from `concept_links` on a ring to the right of the existing nodes; an evidence or note can be on a board once; limits 300 nodes / 1000 edges. Frontend `components/workspace/BoardView.tsx` is HTML nodes in a transformed div with an SVG edge layer (no graph library; node heights come from a ResizeObserver; math in `lib/board.ts`, `tests/board.test.ts`). Study: `src/srs.py` (pure SM-2; grades again/hard/good/easy = quality 1/3/4/5; the interval uses the just-updated ease; a failed card goes to 1 day) and `src/study.py` (cards reference an evidence item; the back is always its quote; `auto_front` only for a definition whose `meta.term` was saved, which the result card's Save button now sends; `due` is a date, so "today" is the server's date). Alerts: `src/alerts.py` (`answers_from`, `new_sources`, `library_fingerprint` = book count + newest id, so a re-ingest counts as a change); `POST /api/workspace/saved-searches/check` runs at most 4 due searches per call through `load_control.gate()` using `workspace_api.context.search` (set in `api_server`), the first run only stores a baseline, notifications are in-app; the dashboard triggers the check, there is no background job. `export_all` includes boards, cards and saved searches. Tests: `tests/test_board.py`, `tests/test_srs.py`, `tests/test_alerts.py`, and the board / cards / saved-search cases in `tests/test_accounts_db.py`.

## Website switch (admin app "Website" page)

`src/website.py` (no DB/models) owns serving and building the frontend: the live switch is server state `website_live` (`runtime_config.get_state`, default `SERVE_FRONTEND`, which is off), read on every request, so toggling or rebuilding needs no restart. `api_server.website_files` is a catch-all GET registered last: it 404s (JSON) for the switch off, `api/`, `data/`, `health/`, `ready/` paths, serves only real files under `frontend/dist` (realpath check; symlinks out are refused) and falls back to `index.html` for extensionless paths; `index.html` is `no-cache`, `assets/*` immutable. `website.Builder` runs `npm install` (when `node_modules`/`package-lock.json` say so) then `npm run build` in a thread, one at a time, ANSI-stripped log kept in memory; `find_npm` falls back to `~/.nvm/versions/node/*/bin/npm`; Node must be 20.19+/22.12+. Admin routes `GET/PUT /api/admin/website`, `POST /api/admin/website/build`; going live needs a build. Admin app: `src/pages/Website.tsx`, `src/lib/caddy.ts` (domain/IP validation and the Caddyfile + steps text, `electron/caddy.test.ts`), and a `shell:openExternal` bridge limited to http(s) (`isOpenableUrl`). Tests: `tests/test_website.py`.

## Evaluating search changes

`tests/eval_search.py` runs 109 hand-labelled questions (`tests/eval/questions.json`, expected file + page set + answer keyword; an optional `group` such as `hi->en`, `roman-bn`, `mixed` or `rare-en` overrides `lang` in the per-group hit@3 breakdown) against the live ingested corpus and reports hit@k / MRR:

```bash
.venv/bin/python tests/eval_search.py --validate              # DB only: check labels against ingested text
.venv/bin/python tests/eval_search.py --mode retrieval        # retrieval only
.venv/bin/python tests/eval_search.py --mode full --depth 3   # full pipeline, fixed top_k
.venv/bin/python tests/eval_search.py --mode full --depth 0   # no top_k: relative threshold, as the website
```

`--compare` runs the set once per feature variant (baseline all off, all on, each of RRF / language fields / question-word stripping / same-language keywords / dedupe+MMR / extra QA candidates off) and prints one table; in `--mode retrieval` only the first four matter. `--set key=value` overrides any `Settings` field (lower-case attribute name).

`tests/test_ranking.py` and `tests/test_search.py` need no services: the latter uses a fake ES client, fake models, and a SentencePiece tokenizer + random tiny XLM-R trained on the fly.

Needs Postgres/ES running and the PDFs in `data/pdfs/` ingested (PDFs, `models/`, `.venv` are gitignored). Several corpus books legitimately answer the same question, so when a "miss" looks correct, widen the label rather than tuning the system. The bn/hi questions were written from the ingested OCR text (definition-style, so easy: a ceiling, not real-world accuracy); the `->en` cross-language groups have only 2 questions each. Treat one- or two-question differences as noise. Two corpus books are scanned (OCR-only) and noisy.

## Admin API and admin app

`src/admin_api.py` serves `/api/admin/*` (needs `ADMIN_TOKEN`, sent as `X-Admin-Token`; 503 when unset). Model-free DB/ES helpers are in `src/admin.py`; metadata edits must update PostgreSQL *and* the book's ES docs (search reads title/author/department from ES). Deleting a book keeps the PDF and records it in `excluded_files`, which `ingest.scan_once` skips. Every path that adds/re-ingests/deletes a book holds `ingest.ingest_lock` (a PG advisory lock), including `ingestion.sh`. `src/ingest_worker.py` runs jobs inside the API process with the API's embedder. `src/runtime_config.py` holds the allowlist of settings changeable at runtime (persisted to `data/admin/settings_overrides.json`); add a field there to expose a new knob. `/data` only serves PDFs under `PDF_DIR`, so other files under `data/` stay private.

`admin/` is the Electron app (own `package.json`): `npm run dev`, `npm test` (node:test on `electron/*.test.ts`), `npm run lint`, `npm run build`, `npm run dist`. The renderer has no Node access and never sees tokens; all server calls go through `electron/main.ts` (only `/health` and `/api/admin/*`). The vault (`electron/vault.ts`) has no Electron imports so it is testable in plain Node.

`src/load_control.py` (answer cache, rate limiter, async search gate, metrics) sits in front of the pipeline in `api_server.api_search`; anything that changes books must call `load_control.cache.invalidate()` (admin routes do, and the worker via `on_corpus_change`); search-group settings are part of the cache key. `MODEL_PRECISION` (fp32 default) and `RERANK_BATCH_SIZE` live in `search.py`. `tests/load_test.py` load-tests a running server (README 11.8).

Several API copies (README 11.9): `STATE_BACKEND=postgres` moves process-local state into PostgreSQL — `runtime_config` stores settings/state in the versioned `server_state` row (copies poll it), `job_store.PostgresJobStore` holds jobs/log (claimed with `FOR UPDATE SKIP LOCKED`; only `INGEST_WORKER=true` processes run them), `admin_api.PostgresAuthFailures` the lockout, `replica.py` heartbeats into `replicas`, and `load_control.corpus_changed()` bumps `server_state.corpus_version`, which is part of every cache key. The default `local` backend keeps the old single-process behaviour, and tests rely on it. `storage.py` abstracts PDF storage (local folder or S3; book `file_path` is then an `s3://` URI and `books.source_version` the ETag); never call `os.path` on book paths directly. `REDIS_URL` swaps in Redis-backed cache and rate limiter. `/ready` is the load-balancer check. `deploy/aws` is Terraform; `terraform test` runs it against a mocked provider.

`deploy/` holds the public-deployment files (`Caddyfile.example`, `osiss-api.service`); `api.sh` honours `API_HOST`/`API_PORT`, and docker-compose publishes Postgres/ES on 127.0.0.1 only. README section 11 is the step-by-step admin guide; its screenshots live in `docs/images/admin/`.

`.mcp.json` (code-review-graph, local paths) and `.code-review-graph/` are gitignored.
